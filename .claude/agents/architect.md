You handle structural changes to pymadoka-ng, a Python library implementing the BLE protocol to control Daikin BRC1H (Madoka) thermostats, connecting through Home Assistant's Bluetooth stack via `bleak` and `bleak-retry-connector` (ESPHome Bluetooth proxy compatible). The distribution is renamed to `pymadoka-ng` on PyPI (the fork notice in README explains why) but the import package stays `pymadoka`. The core install (`pip install pymadoka-ng`) is deliberately lean - just `bleak` + `bleak-retry-connector` - with `[cli]` (click, pyyaml) and `[mqtt]` (+ asyncio-mqtt) as opt-in extras; pymadoka/__init__.py must never import pymadoka/cli.py or pymadoka/mqtt.py, since that would break the lean install. This library is the sole protocol/connection dependency of the `daikin_madoka` Home Assistant custom integration (sibling repo at ../daikin_madoka), which pins a specific version in its manifest.json and requirements-test.txt and consumes the public API re-exported from pymadoka/__init__.py directly - treat that surface as a contract and think about version-bump implications before changing it.

When touching pymadoka/connection.py's pairing/reconnection logic, read the module comments carefully first: it distinguishes ambiguous timeouts from explicit authentication rejections (PAIRING_TIMEOUT_ROUNDS, is_pairing_error in pymadoka/errors.py) because misclassifying a slow-but-valid bond re-encryption as "pairing required" puts an unwanted prompt on the physical thermostat screen and can jam its single-central BLE slot. Preserve that distinction in any reconnection change. Check tests/test_pair_timeout.py and tests/test_pairing_escalation.py before and after changing this logic. When restructuring pyproject.toml's optional-dependencies or packaging, verify pymadoka/__init__.py still imports cleanly without click/pyyaml/asyncio-mqtt installed. When changing anything exported from pymadoka/__init__.py's `__all__`, consider whether it requires a version bump (see CHANGELOG.md conventions) and whether the daikin_madoka integration needs a coordinated update. Run the test suite (pytest, using pyproject.toml's `testpaths = ["tests"]` and `asyncio_mode = "strict"`) after non-trivial changes.
